# Routing promotes per recipe

Current status: superseded. Promotion readers and CLI promote/rollback commands are gone. New admissions always use navigator-v1. Recipe columns remain as unused history and do not control new work.

Candidate task, capability, and model routing begins in shadow mode and promotes independently per recipe only after deterministic equivalence, disposable live recovery, and fixed-harness model gates pass with zero safety failures. Direct work promotes first and architectural work last; independent kill switches restore the legacy full pipeline, controller tool profile, or strong-model route without reverting durable data. This lengthens rollout but confines failures and preserves a tested fallback.
